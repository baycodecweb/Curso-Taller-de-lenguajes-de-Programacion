III. Marco Teórico Breve

📄 1. Clases Abstractas

Son clases que no se pueden instanciar directamente (no puedes escribir new ItemRecompensa(...)); sirven como plantillas o clases base para otras clases hijas. Pueden contener métodos normales y métodos abstractos (métodos sin cuerpo que obligatoriamente deben ser implementados por las subclases).

Piénsalo como un formulario en blanco: una clase abstracta define QUÉ debe saber hacer cualquier cosa basada en ella (por ejemplo, "todo ítem debe saber aplicarEfecto()"), pero no dice CÓMO — eso lo decide cada subclase. Por eso Java no te deja crear un objeto directo de ella: sería como intentar usar el formulario en blanco en vez de una copia ya llenada.

🎭 2. Polimorfismo

Es la capacidad que tienen los objetos de diferentes clases para responder a un mismo mensaje o método, ejecutando acciones distintas según su propia naturaleza (gracias a la sobrescritura de métodos con @Override). Permite manejar múltiples tipos de objetos bajo una misma referencia común (como un arreglo o lista de la clase padre).

Es como el botón "reproducir" de un control remoto universal: la orden que envías es siempre la misma, pero el televisor, el equipo de sonido o el reproductor de DVD (cada uno una "subclase" distinta) responden a su propia manera al recibirla.

⚠️ Errores Comunes al Empezar

❌ Error típico: Intentar escribir new ItemRecompensa(...) directamente sobre la clase abstracta.

✅ Cómo evitarlo: Las clases abstractas NUNCA se instancian directamente; crea un objeto de una subclase concreta, como new ItemAvatar(...).

❌ Error típico: Olvidar @Override (o escribir mal el nombre) al sobrescribir aplicarEfecto() en la subclase.

✅ Cómo evitarlo: @Override no es obligatorio, pero es tu red de seguridad: si el nombre no coincide EXACTO con el método del padre, el compilador te avisa en vez de dejarte crear un método nuevo por accidente.

❌ Error típico: Olvidar el super(...) en el constructor de la subclase cuando la clase padre no tiene un constructor vacío.

✅ Cómo evitarlo: Si la clase abstracta tiene un constructor con parámetros, cada subclase debe llamarlo explícitamente con super(...) como primera línea de su propio constructor.

IV. Actividades Prácticas Paso a Paso

PASO 1

Desarrollo del Trabajo 1 (Creación de Clases Abstractas y Herencia)

Crea una clase abstracta llamada ItemRecompensa.java que servirá como la base para cualquier artículo de la tienda, y al menos dos subclases hijas (ItemAvatar e ItemPaseAcademico).

JAVA 
// Clase Madre Abstracta (Trabajo 1)
public abstract class ItemRecompensa {
    private String nombre;
    private int costoPuntos;

    public ItemRecompensa(String nombre, int costoPuntos) {
        this.nombre = nombre;
        this.costoPuntos = costoPuntos;
    }

    // Método abstracto que las subclases deben implementar obligatoriamente
    public abstract void aplicarEfecto();

    // Métodos Getters
    public String getNombre() { return nombre; }
    public int getCostoPuntos() { return costoPuntos; }
}

// Subclase 1: ItemAvatar (Trabajo 1)
public class ItemAvatar extends ItemRecompensa {
    private String tipoSkin;

    public ItemAvatar(String nombre, int costoPuntos, String tipoSkin) {
        super(nombre, costoPuntos);
        this.tipoSkin = tipoSkin;
    }

    @Override
    public void aplicarEfecto() {
        System.out.println("Desbloqueando skin de avatar tipo: " + tipoSkin);
    }
}

// Subclase 2: ItemPaseAcademico (Trabajo 1)
public class ItemPaseAcademico extends ItemRecompensa {
    private int duracionDias;

    public ItemPaseAcademico(String nombre, int costoPuntos, int duracionDias) {
        super(nombre, costoPuntos);
        this.duracionDias = duracionDias;
    }

    @Override
    public void aplicarEfecto() {
        System.out.println("Otorgando pase académico especial por " + duracionDias + " días.");
    }
}
PASO 2

Desarrollo del Trabajo 2 (Implementación de Polimorfismo)

Crea una clase de prueba PrincipalPrueba.java donde se demuestre el uso de un arreglo polimórfico. Guardaremos diferentes tipos de recompensas en una misma lista y llamaremos a sus métodos de forma genérica.

JAVA 
public class PrincipalPrueba {
    public static void main(String[] args) {
        // Creación de un arreglo polimórfico de tipo ItemRecompensa (Trabajo 2)
        ItemRecompensa[] inventarioTienda = new ItemRecompensa[2];

        inventarioTienda[0] = new ItemAvatar("Skin Guerrero Cyber", 150, "Legendario");
        inventarioTienda[1] = new ItemPaseAcademico("Pase de Prórroga", 300, 7);

        System.out.println("--- EJECUTANDO EFECTOS CON POLIMORFISMO ---");

        // Recorriendo el arreglo e invocando el método de forma polimórfica (Trabajo 2)
        for (ItemRecompensa item : inventarioTienda) {
            System.out.println("Ítem: " + item.getNombre() + " | Costo: " + item.getCostoPuntos() + " pts");
            item.aplicarEfecto(); // Comportamiento dinámico según la subclase
            System.out.println("--------------------------------------------------");
        }
    }
}

🤔 Antes de seguir: si guardas un ItemAvatar y un ItemPaseAcademico en el mismo arreglo de tipo ItemRecompensa[] y llamas a aplicarEfecto() en cada uno dentro de un for, ¿el mensaje impreso será igual o distinto para cada uno?

Distinto — aunque ambos objetos se recorren a través de la misma referencia ItemRecompensa, cada uno ejecuta SU PROPIA versión de aplicarEfecto(). Eso es exactamente el polimorfismo en acción: mismo método, comportamiento distinto según el objeto real.
