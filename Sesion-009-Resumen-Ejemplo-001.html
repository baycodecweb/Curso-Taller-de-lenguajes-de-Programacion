Programación Orientada a Eventos y Componentes Gráficos Básicos (Java Swing)

Progreso de entrega 0 / 6 completado

Objetivo de la Guía

Construir la primera interfaz gráfica de usuario (GUI) en Java utilizando componentes básicos (JFrame, JLabel, JTextField, JButton) y programar la interactividad mediante la Programación Orientada a Eventos (POE) con Listeners.

Marco Teórico Breve

1. ¿Qué es una librería (biblioteca) de código?

Antes de hablar de Swing, conviene entender qué es una librería (también llamada biblioteca) en programación: es un conjunto de clases y funciones que otras personas ya programaron, probaron y empaquetaron para que cualquier desarrollador las reutilice, en lugar de escribir todo desde cero.

Es como una caja de herramientas: si necesitas atornillar algo, no fabricas un destornillador nuevo, tomas el que ya existe en la caja y lo usas. En Java pasa lo mismo: cuando escribes import javax.swing.*;, le estás diciendo al programa "quiero usar las herramientas (clases) que trae el paquete javax.swing". Gracias a eso, no necesitas programar tú mismo cómo se dibuja un botón en pantalla: simplemente usas la clase JButton que la librería ya te ofrece, lista para usar.

2. ¿Qué es Java Swing y los Componentes Básicos?

Java Swing es, precisamente, un ejemplo concreto de librería: es la biblioteca gráfica de Java que permite crear aplicaciones de escritorio sin programar el dibujo de cada botón o ventana a bajo nivel. Los elementos principales son:

  • JFrame: La ventana principal de la aplicación.
  • JLabel: Etiquetas para mostrar texto o imágenes estáticas.
  • JTextField: Cajas de texto donde el usuario puede escribir información (ej. su nombre de usuario).
  • JButton: Botones interactivos que ejecutan acciones al ser presionados.

3. Programación Orientada a Eventos (POE)

A diferencia de los programas secuenciales tradicionales, en una interfaz gráfica el flujo del programa depende de las acciones del usuario (eventos como hacer clic en un botón, mover el mouse, etc.). Se utiliza la interfaz ActionListener para "escuchar" cuándo ocurre un clic y reaccionar ante él.

PASO 2

Desarrollo del Trabajo 2 (Programación de Eventos de Clic)

Ahora, añade la lógica de eventos utilizando un ActionListener al botón btnIngresar. Esto permitirá que al hacer clic se capture el texto digitado y se muestre un mensaje emergente de bienvenida.

Modifica el constructor o añade la siguiente estructura dentro de tu código:

JAVA 
import javax.swing.*;
import java.awt.*;
import java.awt.event.ActionEvent;
import java.awt.event.ActionListener; // Importar para los eventos

public class GameStoreLogin extends JFrame {
    private JLabel lblTitulo, lblUsuario;
    private JTextField txtUsuario;
    private JButton btnIngresar;

    public GameStoreLogin() {
        setTitle("GameStore Escolar - Acceso");
        setSize(350, 200);
        setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        setLocationRelativeTo(null);
        setLayout(null);

        lblTitulo = new JLabel("BIENVENIDO A GAMESTORE");
        lblTitulo.setBounds(70, 20, 200, 25);
        add(lblTitulo);

        lblUsuario = new JLabel("Usuario:");
        lblUsuario.setBounds(40, 70, 80, 25);
        add(lblUsuario);

        txtUsuario = new JTextField();
        txtUsuario.setBounds(110, 70, 180, 25);
        add(txtUsuario);

        btnIngresar = new JButton("Ingresar");
        btnIngresar.setBounds(110, 110, 100, 30);
        add(btnIngresar);

        // --- PROGRAMACIÓN DEL EVENTO DE CLIC (TRABAJO 2) ---
        btnIngresar.addActionListener(new ActionListener() {
            @Override
            public void actionPerformed(ActionEvent e) {
                // Capturar el texto ingresado en el JTextField
                String usuarioIngresado = txtUsuario.getText();

                // Validar si el campo no está vacío
                if (!usuarioIngresado.isEmpty()) {
                    JOptionPane.showMessageDialog(null,
                        "¡Acceso concedido! Bienvenido, " + usuarioIngresado + ".",
                        "GameStore", JOptionPane.INFORMATION_MESSAGE);
                } else {
                    JOptionPane.showMessageDialog(null,
                        "Por favor, ingrese un nombre de usuario.",
                        "Advertencia", JOptionPane.WARNING_MESSAGE);
                }
            }
        });
    }

    public static void main(String[] args) {
        new GameStoreLogin().setVisible(true);
    }
}

Contenedores Avanzados y Administradores de Diseño (Layouts) en Java Swing

Progreso de entrega 0 / 4 completado

Objetivo de la Guía

Diseñar interfaces gráficas complejas y organizadas en Java Swing utilizando contenedores avanzados (JPanel, JScrollPane), administradores de diseño (GridLayout, BorderLayout) y componentes interactivos de selección (JCheckBox, JRadioButton, JComboBox).

Marco Teórico Breve

1. Administradores de Diseño (Layout Managers)

En la Guía N° 1 usaste setLayout(null) y coordenadas fijas (setBounds) para ubicar cada componente a mano — algo parecido a pegar los muebles al piso con cinta métrica: si el "cuarto" (la ventana) cambia de tamaño, los muebles no se mueven solos y todo se desordena.

Un administrador de diseño (Layout Manager) resuelve esto: en vez de darle a Java coordenadas exactas, le das reglas de organización (por ejemplo, "divide la ventana en 5 zonas" o "acomoda todo en una cuadrícula de 3×2"), y es la propia librería Swing la que calcula automáticamente la posición y el tamaño de cada componente, incluso si el usuario redimensiona la ventana.

Los dos que usarás en esta guía:

  • BorderLayout: Divide el contenedor en cinco regiones (BorderLayout.NORTH, SOUTH, EAST, WEST, CENTER).
  • GridLayout: Organiza los componentes en una cuadrícula de filas y columnas con celdas de igual tamaño.

2. Contenedores Avanzados y Componentes de Selección

  • JPanel: Un subcontenedor que permite agrupar varios componentes para organizarlos mejor dentro de un JFrame.
  • JScrollPane: Añade barras de desplazamiento automáticas a un panel cuando el contenido sobrepasa el tamaño visible.
  • JComboBox, JCheckBox, JRadioButton: Componentes que permiten al usuario elegir opciones mediante listas desplegables, casillas de verificación o botones de opción única.

Polimorfismo, Clases Abstractas e Interfaces en Java

Progreso de entrega 0 / 4 completado

Objetivo de la Guía

Programar la lógica de negocio orientada a objetos creando clases abstractas, aplicando herencia y ejecutando polimorfismo dinámico para gestionar los diversos tipos de recompensas del sistema.

Marco Teórico Breve

1. Clases Abstractas

Son clases que no se pueden instanciar directamente (no puedes escribir new ItemRecompensa(...)); sirven como plantillas o clases base para otras clases hijas. Pueden contener métodos normales y métodos abstractos (métodos sin cuerpo que obligatoriamente deben ser implementados por las subclases).

Piénsalo como un formulario en blanco: una clase abstracta define QUÉ debe saber hacer cualquier cosa basada en ella (por ejemplo, "todo ítem debe saber aplicarEfecto()"), pero no dice CÓMO — eso lo decide cada subclase. Por eso Java no te deja crear un objeto directo de ella: sería como intentar usar el formulario en blanco en vez de una copia ya llenada.

2. Polimorfismo

Es la capacidad que tienen los objetos de diferentes clases para responder a un mismo mensaje o método, ejecutando acciones distintas según su propia naturaleza (gracias a la sobrescritura de métodos con @Override). Permite manejar múltiples tipos de objetos bajo una misma referencia común (como un arreglo o lista de la clase padre).

Es como el botón "reproducir" de un control remoto universal: la orden que envías es siempre la misma, pero el televisor, el equipo de sonido o el reproductor de DVD (cada uno una "subclase" distinta) responden a su propia manera al recibirla.

// Clase Madre Abstracta (Trabajo 1)
public abstract class ItemRecompensa {
    private String nombre;
    private int costoPuntos;

    public ItemRecompensa(String nombre, int costoPuntos) {
        this.nombre = nombre;
        this.costoPuntos = costoPuntos;
    }

    // Método abstracto que las subclases deben implementar obligatoriamente
    public abstract void aplicarEfecto();

    // Métodos Getters
    public String getNombre() { return nombre; }
    public int getCostoPuntos() { return costoPuntos; }
}

// Subclase 1: ItemAvatar (Trabajo 1)
public class ItemAvatar extends ItemRecompensa {
    private String tipoSkin;

    public ItemAvatar(String nombre, int costoPuntos, String tipoSkin) {
        super(nombre, costoPuntos);
        this.tipoSkin = tipoSkin;
    }

    @Override
    public void aplicarEfecto() {
        System.out.println("Desbloqueando skin de avatar tipo: " + tipoSkin);
    }
}

// Subclase 2: ItemPaseAcademico (Trabajo 1)
public class ItemPaseAcademico extends ItemRecompensa {

Manejo de Archivos de Texto (Text-File), Binarios y Excepciones en Java

Progreso de entrega 0 / 4 completado

Objetivo de la Guía

Marco Teórico Breve

1. Archivos de Texto (Text-File) vs. Archivos Binarios

  • Archivos de Texto: Almacenan información en caracteres legibles por humanos (como .txt). Se utiliza FileWriter, PrintWriter o BufferedReader.
  • Archivos Binarios: Almacenan los datos directamente en formato de bytes (como objetos serializados). Son más eficientes para respaldos o estructuras complejas y se utiliza FileOutputStream, ObjectOutputStream, etc.

2. Manejo de Excepciones (try-catch)

Las operaciones con archivos son propensas a errores externos (disco lleno, archivo inexistente, permisos denegados). Por ello, es obligatorio envolver el código en bloques try-catch para capturar excepciones como IOException.

Piensa en los flujos (streams) como tubos de agua encadenados: FileWriter es el tubo que llega directo al archivo, y PrintWriter es un embudo con forma más cómoda que conectas ENCIMA de ese tubo para verter el texto más fácilmente. Si el tubo se rompe a mitad de camino (el disco se llena, no hay permisos...), Java lanza una IOException, y el bloque catch es la bandeja que atrapa el derrame para que tu programa no se caiga por completo.

1. Bases de Datos Relacionales y MySQL

Una base de datos relacional organiza los datos en tablas compuestas por filas (registros) y columnas (campos), las cuales se relacionan entre sí mediante claves primarias (PRIMARY KEY) y claves foráneas (FOREIGN KEY). MySQL es uno de los sistemas de gestión de bases de datos relacionales (RDBMS) más populares y compatibles con entornos de desarrollo en Java.

Piensa en una base de datos relacional como un archivador de oficina con carpetas (tablas): cada carpeta tiene fichas (filas) con casillas (columnas). La PRIMARY KEY es como el número de ficha único que nunca se repite dentro de esa carpeta; la FOREIGN KEY es una nota en una ficha que dice "ver la ficha N° X en la carpeta Y" — así conectas información entre carpetas sin duplicarla.

2. Comandos Esenciales de SQL

  • DDL (Lenguaje de Definición de Datos): CREATE DATABASE, CREATE TABLE, DROP TABLE. Permiten estructurar el esquema de la base de datos.
  • DML (Lenguaje de Manipulación de Datos): INSERT INTO, SELECT, UPDATE, DELETE. Permiten insertar, consultar, modificar y eliminar los registros de las tablas.

Conectividad a Bases de Datos con JDBC en Java

Progreso de entrega 0 / 4 completado

Objetivo de la Guía

Marco Teórico Breve

1. Java Database Connectivity (JDBC)

Es la API estándar de Java que permite la ejecución de operaciones contra bases de datos relacionales. Utiliza un driver específico del motor (como MySQL Connector) para puentear la aplicación con el servidor de bases de datos mediante la clase DriverManager y la interfaz Connection.

Piensa en JDBC como un adaptador de enchufe universal: tu programa Java "habla" un idioma, y cada motor de base de datos (MySQL, PostgreSQL, etc.) "habla" otro. El driver (MySQL Connector/J) es el adaptador específico que traduce entre ambos; DriverManager es quien elige automáticamente el adaptador correcto según la URL que le des (jdbc:mysql://...).

2. Consultas Preparadas (PreparedStatement)

A diferencia de Statement, la interfaz PreparedStatement permite compilar la consulta SQL previamente y pasarle parámetros de forma segura (?), previniendo ataques de inyección SQL y mejorando el rendimiento en consultas repetitivas. El manejo de los resultados de lectura se realiza mediante la interfaz ResultSet.

Piensa en PreparedStatement como un formulario impreso con espacios en blanco (los ?): la "pregunta" ya está fija e impresa, y tú solo rellenas los espacios con datos. Como el formulario nunca cambia de estructura, no hay forma de que alguien "cuele" código SQL malicioso escribiendo algo raro en un espacio en blanco — eso es justamente lo que previene la inyección SQL.

Marco Teórico Breve

🏛️ Arquitectura de Servlets

Todo lo aprendido hasta ahora corre en el computador del usuario como una aplicación de escritorio. Un Servlet traslada esa lógica a la web: es una clase Java que vive dentro de un servidor (un contenedor de Servlets como Apache Tomcat) y genera páginas HTML dinámicas en respuesta a las peticiones de un navegador.

  • Contenedor de Servlets (Tomcat): recibe cada petición HTTP, crea el Servlet correspondiente y controla su ciclo de vida: init() al arrancar, service() por cada petición, y destroy() al detener la aplicación.
  • HttpServletRequest: el objeto con todo lo que envió el navegador (parámetros de un formulario, cabeceras, etc.).
  • HttpServletResponse: el objeto que el Servlet usa para construir y devolver la respuesta (normalmente HTML) al navegador.
  • Librerías necesarias: el paquete jakarta.servlet.http (antes javax.servlet.http) con HttpServlet, HttpServletRequest / HttpServletResponse, y la anotación @WebServlet para registrar la URL del Servlet sin necesitar el archivo web.xml.

📨 Procesamiento de Peticiones: doGet vs. doPost

El contenedor llama automáticamente a uno de estos dos métodos, según el método HTTP de la petición:

  • doGet: atiende peticiones GET, las que se disparan al escribir una URL o seguir un enlace. Se usa para mostrar una página, como el formulario de acceso.
  • doPost: atiende peticiones POST, las que genera un formulario HTML con method="post". Se usa para enviar datos, como las credenciales del usuario.

📄 JSP: la Vista del Lado del Servidor

JSP (JavaServer Pages) es la otra mitad de la tecnología: en vez de imprimir HTML línea por línea con out.println(...) (como en un Servlet puro), un archivo .jsp se escribe casi como HTML normal, con pequeños fragmentos de Java incrustados entre <% %> (código) y <%= %> (para imprimir un valor). Por ejemplo:

<h2>Bienvenido, <%= request.getParameter("usuario") %></h2>

Detrás de escena, el contenedor compila cada JSP a un Servlet la primera vez que se pide. Por eso en la práctica se combinan: el Servlet recibe la petición y aplica la lógica (validar, consultar la base de datos), y la JSP se encarga solo de mostrar el resultado.

⚠️ Errores comunes: confundir doGet con doPost (el method del <form> decide cuál se ejecuta); olvidar la anotación @WebServlet (el contenedor nunca encontraría la clase); y mezclar demasiado HTML dentro del Servlet con muchos out.println(...) en vez de delegar la presentación a una JSP.

Servlet de Acceso (doGet y doPost)

El siguiente Servlet lleva el login de las Sesiones 1 y 7 a la web: doGet dibuja el formulario y doPost procesa lo enviado.

JAVA 
import java.io.IOException;
import java.io.PrintWriter;
import jakarta.servlet.ServletException;
import jakarta.servlet.annotation.WebServlet;
import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

@WebServlet("/login")
public class GameStoreLoginServlet extends HttpServlet {

    @Override
    protected void doGet(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        response.setContentType("text/html;charset=UTF-8");
        try (PrintWriter out = response.getWriter()) {
            out.println("<html><body>");
            out.println("<h2>GameStore Escolar - Acceso Web</h2>");
            out.println("<form method='post' action='login'>");
            out.println("Usuario: <input type='text' name='usuario'><br>");
            out.println("<input type='submit' value='Ingresar'>");
            out.println("</form>");
            out.println("</body></html>");
        }
    }

    @Override
    protected void doPost(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        String usuario = request.getParameter("usuario");
        response.setContentType("text/html;charset=UTF-8");

        try (PrintWriter out = response.getWriter()) {
            out.println("<html><body>");
            if (usuario != null && !usuario.trim().isEmpty()) {
                out.println("<h2>Bienvenido, " + usuario + "</h2>");
            } else {
                out.println("<h2>Error: ingrese un usuario</h2>");
            }
            out.println("</body></html>");
        }
    }
}
