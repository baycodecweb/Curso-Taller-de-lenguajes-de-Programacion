III. Marco Teórico Breve

🗄️ 1. Bases de Datos Relacionales y MySQL

Una base de datos relacional organiza los datos en tablas compuestas por filas (registros) y columnas (campos), las cuales se relacionan entre sí mediante claves primarias (PRIMARY KEY) y claves foráneas (FOREIGN KEY). MySQL es uno de los sistemas de gestión de bases de datos relacionales (RDBMS) más populares y compatibles con entornos de desarrollo en Java.

Piensa en una base de datos relacional como un archivador de oficina con carpetas (tablas): cada carpeta tiene fichas (filas) con casillas (columnas). La PRIMARY KEY es como el número de ficha único que nunca se repite dentro de esa carpeta; la FOREIGN KEY es una nota en una ficha que dice "ver la ficha N° X en la carpeta Y" — así conectas información entre carpetas sin duplicarla.

📝 2. Comandos Esenciales de SQL

  • DDL (Lenguaje de Definición de Datos): CREATE DATABASE, CREATE TABLE, DROP TABLE. Permiten estructurar el esquema de la base de datos.
  • DML (Lenguaje de Manipulación de Datos): INSERT INTO, SELECT, UPDATE, DELETE. Permiten insertar, consultar, modificar y eliminar los registros de las tablas.

⚠️ Errores Comunes al Empezar

❌ Error típico: Ejecutar DELETE FROM tabla; sin ninguna cláusula WHERE.

✅ Cómo evitarlo: Sin WHERE se borran TODAS las filas de la tabla, no solo una. Revisa siempre esa cláusula antes de ejecutar un DELETE o un UPDATE.

❌ Error típico: Insertar en una FOREIGN KEY un valor que no existe en la tabla relacionada.

✅ Cómo evitarlo: El valor de una clave foránea debe existir primero como clave primaria en la tabla a la que apunta, o MySQL rechaza el INSERT por integridad referencial.

❌ Error típico: Olvidar las comillas en valores de texto dentro de un INSERT o WHERE, por ejemplo WHERE nombre = Carlos.

✅ Cómo evitarlo: Los valores de texto siempre van entre comillas simples: WHERE nombre = 'Carlos'.

IV. Actividades Prácticas Paso a Paso

PASO 1

Desarrollo del Trabajo 1 (Diseño de Esquema Relacional en MySQL)

Abre tu consola de MySQL o tu herramienta de administración (como MySQL Workbench o DBeaver) y ejecuta el siguiente script DDL para crear la base de datos y las tablas vinculadas del proyecto GameStore Escolar:

SQL 
-- Creación de la base de datos (Trabajo 1)
CREATE DATABASE IF NOT EXISTS gamestore_db;
USE gamestore_db;

-- Tabla Estudiantes (Trabajo 1)
CREATE TABLE estudiantes (
    id_estudiante INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    puntos INT DEFAULT 0
);

-- Tabla Recompensas (Trabajo 1)
CREATE TABLE recompensas (
    id_recompensa INT AUTO_INCREMENT PRIMARY KEY,
    nombre_item VARCHAR(100) NOT NULL,
    costo_puntos INT NOT NULL
);

-- Tabla Historial de Canjes con Llaves Foráneas (Trabajo 1)
CREATE TABLE historial_canjes (
    id_canje INT AUTO_INCREMENT PRIMARY KEY,
    id_estudiante INT,
    id_recompensa INT,
    fecha_canje TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (id_estudiante) REFERENCES estudiantes(id_estudiante),
    FOREIGN KEY (id_recompensa) REFERENCES recompensas(id_recompensa)
);
PASO 2

Desarrollo del Trabajo 2 (Ejecución de Consultas SQL)

Inserta datos de prueba y practica consultas DML para interactuar con la información del sistema de manera relacional:

SQL 
-- Inserción de registros iniciales (Trabajo 2)
INSERT INTO estudiantes (nombre, puntos) VALUES ('Carlos Mendoza', 500), ('Ana Torres', 350);
INSERT INTO recompensas (nombre_item, costo_puntos) VALUES ('Skin Guerrero Cyber', 150), ('Pase de Prórroga', 300);

-- Consulta general de estudiantes
SELECT * FROM estudiantes;

-- Actualización de puntajes (Trabajo 2)
UPDATE estudiantes SET puntos = 600 WHERE id_estudiante = 1;

-- Registro de un canje relacionando las tablas (Trabajo 2)
INSERT INTO historial_canjes (id_estudiante, id_recompensa) VALUES (1, 1);

-- Consulta avanzada con JOIN para ver el historial detallado de canjes (Trabajo 2)
SELECT h.id_canje, e.nombre AS estudiante, r.nombre_item, r.costo_puntos, h.fecha_canje
FROM historial_canjes h
JOIN estudiantes e ON h.id_estudiante = e.id_estudiante
JOIN recompensas r ON h.id_recompensa = r.id_recompensa;

🤔 Antes de seguir: si ejecutaras UPDATE estudiantes SET puntos = 0; SIN ningún WHERE, ¿a cuántos estudiantes les cambiaría los puntos?

A TODOS los de la tabla — sin WHERE, un UPDATE (igual que un DELETE) afecta cada fila existente. Por eso siempre se revisa dos veces esa cláusula antes de ejecutar.
