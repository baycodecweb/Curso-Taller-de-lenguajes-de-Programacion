III. Marco Teórico Breve

🔌 1. Java Database Connectivity (JDBC)

Es la API estándar de Java que permite la ejecución de operaciones contra bases de datos relacionales. Utiliza un driver específico del motor (como MySQL Connector) para puentear la aplicación con el servidor de bases de datos mediante la clase DriverManager y la interfaz Connection.

Piensa en JDBC como un adaptador de enchufe universal: tu programa Java "habla" un idioma, y cada motor de base de datos (MySQL, PostgreSQL, etc.) "habla" otro. El driver (MySQL Connector/J) es el adaptador específico que traduce entre ambos; DriverManager es quien elige automáticamente el adaptador correcto según la URL que le des (jdbc:mysql://...).

🛡️ 2. Consultas Preparadas (PreparedStatement)

A diferencia de Statement, la interfaz PreparedStatement permite compilar la consulta SQL previamente y pasarle parámetros de forma segura (?), previniendo ataques de inyección SQL y mejorando el rendimiento en consultas repetitivas. El manejo de los resultados de lectura se realiza mediante la interfaz ResultSet.

Piensa en PreparedStatement como un formulario impreso con espacios en blanco (los ?): la "pregunta" ya está fija e impresa, y tú solo rellenas los espacios con datos. Como el formulario nunca cambia de estructura, no hay forma de que alguien "cuele" código SQL malicioso escribiendo algo raro en un espacio en blanco — eso es justamente lo que previene la inyección SQL.

⚠️ Errores Comunes al Empezar

❌ Error típico: Escribir mal el host, el puerto o el nombre de la base de datos en la URL de conexión.

✅ Cómo evitarlo: Revisa que el servidor MySQL esté encendido y que la URL tenga exactamente el mismo nombre de base de datos que creaste en la Sesión 6.

❌ Error típico: Concatenar directamente valores del usuario dentro del SQL de un Statement en vez de usar PreparedStatement con ?.

✅ Cómo evitarlo: Usa siempre PreparedStatement con ? para cualquier valor que venga de un formulario o del usuario; evita errores de sintaxis y ataques de inyección SQL.

❌ Error típico: Olvidar cerrar la Connection, o no usar try-with-resources.

✅ Cómo evitarlo: Igual que con los archivos, usa try-with-resources para que Java cierre la conexión automáticamente, incluso si algo falla.

IV. Actividades Prácticas Paso a Paso

PASO 1

Desarrollo del Trabajo 1 (Clase de Conexión Centralizada)

Crea una clase llamada ConexionBD.java para gestionar de forma centralizada la conexión con la base de datos MySQL creada en la sesión anterior (gamestore_db). Asegúrate de incluir el archivo JAR del conector de MySQL en las librerías de tu proyecto.

JAVA 
import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.SQLException;

public class ConexionBD {
    // Parámetros de conexión (Trabajo 1)
    private static final String URL = "jdbc:mysql://localhost:3306/gamestore_db?useSSL=false&serverTimezone=UTC";
    private static final String USUARIO = "root";
    private static final String PASSWORD = ""; // Cambiar según la configuración local

    // Método para obtener la conexión (Trabajo 1)
    public static Connection obtenerConexion() {
        Connection conexion = null;
        try {
            conexion = DriverManager.getConnection(URL, USUARIO, PASSWORD);
            System.out.println("¡Conexión exitosa a la base de datos MySQL!");
        } catch (SQLException e) {
            System.out.println("Error al conectar con la base de datos: " + e.getMessage());
        }
        return conexion;
    }
}
PASO 2

Desarrollo del Trabajo 2 (Implementación del CRUD mediante Consultas Preparadas)

Crea una clase llamada EstudianteDAO.java que permita realizar las operaciones de inserción y consulta (CRUD) utilizando PreparedStatement y ResultSet.

JAVA 
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;

public class EstudianteDAO {

    // Método para registrar un nuevo estudiante (Create - Trabajo 2)
    public void insertarEstudiante(String nombre, int puntos) {
        String sql = "INSERT INTO estudiantes (nombre, puntos) VALUES (?, ?)";

        try (Connection conn = ConexionBD.obtenerConexion();
             PreparedStatement pstmt = conn.prepareStatement(sql)) {

            pstmt.setString(1, nombre);
            pstmt.setInt(2, puntos);
            pstmt.executeUpdate();
            System.out.println("Estudiante registrado exitosamente en la BD.");

        } catch (SQLException e) {
            System.out.println("Error al insertar estudiante: " + e.getMessage());
        }
    }

    // Método para listar estudiantes (Read - Trabajo 2)
    public void listarEstudiantes() {
        String sql = "SELECT id_estudiante, nombre, puntos FROM estudiantes";

        try (Connection conn = ConexionBD.obtenerConexion();
             PreparedStatement pstmt = conn.prepareStatement(sql);
             ResultSet rs = pstmt.executeQuery()) {

            System.out.println("--- LISTA DE ESTUDIANTES (DESDE MYSQL) ---");
            while (rs.next()) {
                int id = rs.getInt("id_estudiante");
                String nombre = rs.getString("nombre");
                int puntos = rs.getInt("puntos");
                System.out.println("ID: " + id + " | Nombre: " + nombre + " | Puntos: " + puntos);
            }

        } catch (SQLException e) {
            System.out.println("Error al consultar estudiantes: " + e.getMessage());
        }
    }
}

🤔 Antes de seguir: si una consulta PreparedStatement tiene dos signos ?, pero solo llamas a setString() una vez antes de ejecutarla, ¿qué crees que pasará?

Se lanza una excepción (SQLException) — cada ? es un parámetro obligatorio; si dejas alguno sin asignar con un método setXxx(), JDBC no puede completar la consulta y el programa falla al ejecutarla.

Clase de ejecución

Puedes crear una clase principal de prueba PrincipalJDBC.java para verificar la ejecución de la capa de persistencia:

JAVA 
public class PrincipalJDBC {
    public static void main(String[] args) {
        EstudianteDAO dao = new EstudianteDAO();

        // Probando la inserción conectada a MySQL (Trabajo 2)
        dao.insertarEstudiante("Lucía Pérez", 420);

        // Probando la lectura de registros (Trabajo 2)
        dao.listarEstudiantes();
    }
}
