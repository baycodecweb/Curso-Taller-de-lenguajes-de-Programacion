III. Marco Teórico Breve

🏛️ Arquitectura Multicapa en Aplicaciones de Escritorio

Para construir software robusto y escalable, las aplicaciones se dividen en capas lógicas:

  • Capa de Presentación (UI): Interfaces creadas con Java Swing (JFrame, JPanel, layouts) que interactúan con el usuario.
  • Capa de Lógica de Negocio (POO): Clases abstractas, herencia y polimorfismo (ItemRecompensa, subclases) que procesan las reglas del sistema.
  • Capa de Persistencia (DAO / JDBC): Clases encargadas de conectar la aplicación con el servidor MySQL mediante consultas preparadas (PreparedStatement).

Piensa en las tres capas como un restaurante: la Presentación es el salón donde el cliente hace su pedido (la GUI); la Lógica de Negocio es la cocina que sabe las recetas y reglas (tus clases POO); y la Persistencia es la despensa donde se guardan y sacan los ingredientes (JDBC + MySQL). Cada una hace su trabajo sin necesitar saber los detalles internos de las otras dos.

⚠️ Errores Comunes al Empezar

❌ Error típico: Hacer que la clase de la vista (GUI) llame directamente a JDBC en vez de usar la clase DAO.

✅ Cómo evitarlo: La vista solo debe llamar a métodos del DAO (por ejemplo estudianteDAO.buscarPorUsuario(...)); el DAO es el único que "sabe" de SQL y JDBC.

❌ Error típico: Traer todos los datos de la tabla y comparar la contraseña en Java, en vez de filtrar en la propia consulta.

✅ Cómo evitarlo: La validación se hace en la consulta SQL con WHERE usuario = ? AND contraseña = ?, usando PreparedStatement; es más eficiente y más seguro.

❌ Error típico: No revisar si el ResultSet trajo alguna fila antes de leer sus columnas (por ejemplo cuando el usuario no existe).

✅ Cómo evitarlo: Siempre revisa con if (rs.next()) si la consulta realmente devolvió una fila antes de intentar leer sus datos, para evitar errores inesperados.

IV. Servlets y Desarrollo Web (JSP)

Todo lo aprendido hasta ahora (Swing, POO, JDBC) corre en el computador del usuario como una aplicación de escritorio. Un Servlet traslada esa misma lógica a la web: es una clase Java que vive dentro de un servidor (un contenedor de Servlets como Apache Tomcat) y genera páginas HTML dinámicas en respuesta a las peticiones que le manda un navegador.

🏛️ Arquitectura de Servlets

  • Contenedor de Servlets (Tomcat): recibe cada petición HTTP del navegador, crea (una sola vez) el Servlet correspondiente y controla su ciclo de vida: init() al arrancar, service() por cada petición, y destroy() al detener la aplicación.
  • HttpServletRequest: el objeto con todo lo que envió el navegador (parámetros de un formulario, cabeceras, etc.).
  • HttpServletResponse: el objeto que el Servlet usa para construir y devolver la respuesta (normalmente HTML) al navegador.
  • Librerías de clases necesarias: el paquete jakarta.servlet.http (antes javax.servlet.http) con HttpServlet, HttpServletRequest/HttpServletResponse, y la anotación @WebServlet para registrar la URL del Servlet, junto con un servidor de aplicaciones (Tomcat) que las provee.

📨 Procesamiento de Peticiones: doGet vs. doPost

El contenedor llama automáticamente a uno de estos dos métodos, según el método HTTP de la petición que llegó:

  • doGet(request, response): atiende peticiones GET, las que se disparan al escribir una URL o seguir un enlace. Se usa para mostrar una página, como el formulario de acceso.
  • doPost(request, response): atiende peticiones POST, las que genera un formulario HTML con method="post". Se usa para enviar datos, como las credenciales del usuario.

📄 JSP: la Vista del Lado del Servidor

JSP (JavaServer Pages) es la otra mitad de la tecnología: en vez de imprimir HTML línea por línea con out.println(...) (como en un Servlet puro), un archivo .jsp se escribe casi como HTML normal, con pequeños fragmentos de Java incrustados entre <% %> (código) y <%= %> (para imprimir un valor). Por ejemplo:

<h2>Bienvenido, <%= request.getParameter("usuario") %></h2>

Detrás de escena, el contenedor compila cada JSP a un Servlet la primera vez que se pide. Por eso en la práctica se combinan: el Servlet recibe la petición y aplica la lógica (validar, consultar la base de datos), y la JSP se encarga solo de mostrar el resultado — la misma separación de responsabilidades vista, por ejemplo con vista/modelo/dao, en el Marco Teórico de esta guía.

⚠️ Errores Comunes con Servlets y JSP

❌ Error típico: Confundir doGet con doPost y no entender por qué un formulario "no llega" al método esperado.

✅ Cómo evitarlo: El method del <form> en el HTML (get o post) es el que decide cuál método del Servlet se ejecuta; deben coincidir con el nombre del método sobrescrito.

❌ Error típico: Olvidar la anotación @WebServlet (o la entrada equivalente en web.xml), por lo que el contenedor nunca encuentra la clase.

✅ Cómo evitarlo: Toda clase que extiende HttpServlet necesita quedar mapeada a una URL, ya sea con @WebServlet("/ruta") o en web.xml.

❌ Error típico: Mezclar demasiado HTML dentro del Servlet con muchos out.println(...), en vez de delegar la presentación a una JSP.

✅ Cómo evitarlo: Usa el Servlet solo para la lógica (parámetros, validación, base de datos) y una JSP para el HTML final, igual que la Vista se separa del DAO en el proyecto de escritorio.

El siguiente Servlet lleva el login de las Sesiones 1 y 8 (Swing) a la web: doGet dibuja el formulario y doPost procesa lo enviado.

JAVA 
import java.io.IOException;
import java.io.PrintWriter;
import jakarta.servlet.ServletException;
import jakarta.servlet.annotation.WebServlet;
import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

@WebServlet("/login")
public class GameStoreLoginServlet extends HttpServlet {

    @Override
    protected void doGet(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        response.setContentType("text/html;charset=UTF-8");
        try (PrintWriter out = response.getWriter()) {
            out.println("<html><body>");
            out.println("<h2>GameStore Escolar - Acceso Web</h2>");
            out.println("<form method='post' action='login'>");
            out.println("Usuario: <input type='text' name='usuario'><br>");
            out.println("<input type='submit' value='Ingresar'>");
            out.println("</form>");
            out.println("</body></html>");
        }
    }

    @Override
    protected void doPost(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        String usuario = request.getParameter("usuario");
        response.setContentType("text/html;charset=UTF-8");

        try (PrintWriter out = response.getWriter()) {
            out.println("<html><body>");
            if (usuario != null && !usuario.trim().isEmpty()) {
                out.println("<h2>Bienvenido, " + usuario + "</h2>");
            } else {
                out.println("<h2>Error: ingrese un usuario</h2>");
            }
            out.println("</body></html>");
        }
    }
}

🤔 Antes de seguir: si el usuario envía el formulario de doGet sin escribir nada en el campo, ¿qué mensaje mostrará doPost?

"Error: ingrese un usuario" — request.getParameter("usuario") devuelve una cadena vacía (o nula), así que usuario.trim().isEmpty() es true y se ejecuta la rama else.

PASO 3

Código de Ejemplo del Flujo Integrado (Ventana de Acceso conectada a la BD)

Aquí tienes una muestra de cómo unificar el evento de clic de la Sesión 1 con la validación directa desde la base de datos (Sesión 7):

JAVA 
import javax.swing.*;
import java.awt.event.ActionEvent;
import java.awt.event.ActionListener;
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;

public class GameStoreLoginIntegrado extends JFrame {
    private JLabel lblUsuario;
    private JTextField txtUsuario;
    private JButton btnIngresar;

    public GameStoreLoginIntegrado() {
        setTitle("GameStore Escolar - Acceso al Sistema");
        setSize(350, 200);
        setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        setLocationRelativeTo(null);
        setLayout(null);

        lblUsuario = new JLabel("Usuario:");
        lblUsuario.setBounds(40, 50, 80, 25);
        add(lblUsuario);

        txtUsuario = new JTextField();
        txtUsuario.setBounds(110, 50, 180, 25);
        add(txtUsuario);

        btnIngresar = new JButton("Ingresar");
        btnIngresar.setBounds(110, 100, 100, 30);
        add(btnIngresar);

        // Evento de clic integrado con JDBC
        btnIngresar.addActionListener(new ActionListener() {
            @Override
            public void actionPerformed(ActionEvent e) {
                String nombreUsuario = txtUsuario.getText().trim();

                if (!nombreUsuario.isEmpty()) {
                    if (validarUsuarioEnBD(nombreUsuario)) {
                        JOptionPane.showMessageDialog(null, "¡Bienvenido, " + nombreUsuario + "!", "Acceso Concedido", JOptionPane.INFORMATION_MESSAGE);
                        // Abrir la ventana del Catálogo (Sesión 2)
                        dispose(); // Cierra el login
                        // new CatalogoTiendaAvanzado().setVisible(true);
                    } else {
                        JOptionPane.showMessageDialog(null, "Usuario no encontrado en la base de datos.", "Error de Acceso", JOptionPane.ERROR_MESSAGE);
                    }
                } else {
                    JOptionPane.showMessageDialog(null, "Ingrese un nombre de usuario.", "Advertencia", JOptionPane.WARNING_MESSAGE);
                }
            }
        });
    }

    // Método para validar credenciales consultando MySQL
    private boolean validarUsuarioEnBD(String nombre) {
        boolean existe = false;
        String sql = "SELECT * FROM estudiantes WHERE nombre = ?";

        try (Connection conn = ConexionBD.obtenerConexion();
             PreparedStatement pstmt = conn.prepareStatement(sql)) {

            pstmt.setString(1, nombre);
            try (ResultSet rs = pstmt.executeQuery()) {
                if (rs.next()) {
                    existe = true; // El usuario existe en la BD
                }
            }
        } catch (SQLException e) {
            System.out.println("Error al validar usuario: " + e.getMessage());
        }
        return existe;
    }

    public static void main(String[] args) {
        new GameStoreLoginIntegrado().setVisible(true);
    }
}

🤔 Antes de seguir: si el usuario escribe mal su contraseña, ¿qué crees que devuelve rs.next() dentro de validarUsuarioEnBD(...)?

false — la consulta con WHERE usuario = ? AND contraseña = ? no encuentra ninguna fila que coincida, así que el ResultSet queda vacío y rs.next() devuelve false, indicando que la validación falló.
