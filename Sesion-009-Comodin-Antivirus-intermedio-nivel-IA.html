Recorrido de código

La versión que le agrega al nivel intermedio un motor de inteligencia artificial local (llamafile + un modelo GGUF), pensada para correr desde una memoria USB sin instalación, en Windows o Linux — qué hace cada archivo y cómo se conecta con los demás, con el código completo al lado.

🗺️ Diagrama de arquitectura

13 paquetes (todos los del nivel intermedio, más el paquete nuevo ia), ~28 clases. Cada rectángulo es una clase con sus métodos públicos; las notas amarillas marcan limitaciones reales que se explican en el archivo correspondiente. El bloque naranja de abajo es literal: son los tres archivos que van juntos en la USB.

🚀 Cómo ejecutar este proyecto

Necesitás el JDK 17 o superior. Los archivos de la carpeta Proyecto/ se mueven juntos siempre — compile.sh/run.sh resuelven todo relativo a su propia ubicación, así que funciona igual sin importar la letra de unidad en Windows o el punto de montaje en Linux. Al ejecutar, además de la ventana y el servicio de fondo, se arranca automáticamente el servidor de IA local (motor-de-inferencia + modelo-baycodec.gguf).

🐧 Linux / macOS

  1. Abrí una terminal dentro de 02-Antivirus-baycodec-nivel-IA/Proyecto/.
  2. Compilá (primera vez, o tras cambiar un .java):./compile.sh
  3. Ejecutá:./run.sh

🪟 Windows

  1. Entrá a la carpeta Proyecto\windows\.
  2. Compilá con doble clic en compile.bat, o desde cmd:windows\compile.bat
  3. Ejecutá con doble clic en run.bat, o desde cmd:windows\run.bat

Si ./compile.sh o ./run.sh dan "Permission denied", corré chmod +x compile.sh run.sh una sola vez (en Windows el binario motor-de-inferencia también necesita renombrarse a motor-de-inferencia.exe, o dejar que GestorModeloIA lo detecte igual: prueba ambos nombres). La primera vez que se ejecuta se crean solos config.properties, carpeta-vigilada/ y cuarentena/. Si el servidor de IA no llega a arrancar (falta el binario, falta el modelo, o ia.habilitada=false), el antivirus igual funciona con firmas y heurística, solo sin la explicación adicional ni el botón de chat.

📖 Glosario para quien nunca programóDos conceptos base de Java (clase y polimorfismo) y los términos nuevos de este nivel.
Clase
Un "molde" que describe una cosa del programa: qué datos guarda (sus campos) y qué sabe hacer (sus métodos). Con new se crean objetos concretos a partir de ese molde. En Java cada archivo .java suele tener una clase con el mismo nombre.
Clase (en este proyecto)
Cada rectángulo del diagrama es una clase con un único trabajo: Cuarentena aísla archivos, BaseFirmas busca firmas, ClienteIA habla con el modelo. Main crea un objeto de cada una y las conecta. Por esa separación se pudo sumar el paquete ia/ casi sin tocar el nivel intermedio.
▸ Pasá el mouse para ver las 36 clases
Polimorfismo
"Muchas formas": usar objetos distintos a través de un mismo tipo, sin que quien los usa sepa cuál es exactamente; cada uno responde a su manera. En Java se logra con herencia (extends: la hija es un tipo de su padre) o con interfaces (un contrato que muchas clases, o lambdas, cumplen).
Polimorfismo (en este proyecto)
Herencia: VentanaPrincipal extiende JFrame y las ventanas de chat y fuentes extienden JDialog, así heredan setVisible() o dispose(). Lambdas: setAlDetectarAmenaza(Consumer<Path>) acepta cualquier acción; ServicioSegundoPlano le pasa una que registra la amenaza y avisa a la ventana, sin que el monitor sepa quién escucha.

Dónde se usa polimorfismo en este proyecto

No hay interfaces propias: el proyecto aprovecha las que ya trae Java. Clic en una fila para abrir el archivo.

Herencia (extends)

Consumer<T> (recibe un dato y hace algo con él)

Runnable (una tarea sin datos de entrada)

ActionListener (qué hacer al hacer clic)

LLM / modelo de lenguaje
Un programa entrenado con muchísimo texto que predice "qué palabra sigue", y así puede responder preguntas o seguir instrucciones en lenguaje natural. Acá corre uno chico (1.5 mil millones de parámetros) en tu propia máquina, no en la nube.
llamafile
Un ejecutable "de verdad portable": el mismo archivo corre en Linux, Windows, macOS y algunos BSD sin instalar nada, aprovechando un truco de formato de archivo (es válido como script Unix y como .exe de Windows a la vez). En este proyecto se renombró a motor-de-inferencia.
GGUF
El formato de archivo en el que se guardan los pesos (los números aprendidos) de un modelo de lenguaje, pensado para cargarse rápido y ocupar poco. La extensión .gguf es una convención, no algo que llamafile exija por nombre.
API compatible con OpenAI
Un formato de pedido/respuesta HTTP (/v1/chat/completions, con una lista de mensajes {role, content}) que popularizó OpenAI y que después adoptaron muchos servidores de modelos locales, llamafile incluido, para que las mismas herramientas cliente sirvan para cualquiera de los dos.
Prompt
El texto que se le manda al modelo como entrada. Acá hay dos: uno "de sistema" (instrucciones fijas sobre cómo debe comportarse) y uno "de usuario" (la pregunta o los datos concretos de esta consulta).
Alucinación
Cuando un modelo de lenguaje inventa algo que suena convincente pero es falso (por ejemplo, decir que lo creó OpenAI cuando en realidad es un modelo open source corriendo local). Es un límite real de estos modelos, no un bug de este proyecto.
ProcessBuilder (para lanzar OTRO programa)
Ya aparecía en el nivel intermedio para correr comandos cortos (id -u). Acá se usa para algo más grande: mantener corriendo en segundo plano un servidor entero (motor-de-inferencia --server) mientras dura la aplicación.
HttpClient (java.net.http)
La forma moderna que tiene Java (desde la version 11) de hacer pedidos HTTP sin depender de una librería externa. Acá arma el JSON del pedido a mano, en vez de usar una librería de JSON, porque el formato es siempre el mismo.
Grado de confianza / veredicto
La IA no reemplaza la decisión de cuarentena (eso lo sigue haciendo la firma o la heurística); solo agrega una explicación con un número de 0.0 a 1.0 de qué tan segura está. Es información extra, no una autorización.
Segunda opinión (patrón de diseño)
La idea central de este nivel: un sistema determinístico y ya probado (firmas + heurística) sigue mandando; la IA se consulta DESPUÉS, solo para explicar en lenguaje humano, nunca para decidir. Si la IA falla o no está disponible, todo lo demás sigue funcionando igual.
Registro relativo a la raíz del proyecto
Todas las rutas del programa (firmas.db, el binario de IA, el modelo, etc.) se calculan a partir de System.getProperty("user.dir"), nunca con una ruta absoluta tipo C:\ o /home/usuario. Por eso el proyecto entero puede vivir en una USB y correr igual sin importar en qué computadora o letra de unidad esté.
