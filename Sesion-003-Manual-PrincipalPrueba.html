1. ¿Qué es este programa?

Este ejercicio es de consola (sin ventanas): modela el inventario de recompensas de GameStore Escolar usando una clase abstracta, dos subclases y un arreglo polimórfico. Cubre los dos trabajos de la Sesión 3:

  • Trabajo 1 (Clases Abstractas y Herencia): la clase madre abstracta ItemRecompensa define el método abstracto aplicarEfecto(), que cada subclase (ItemAvatar, ItemPaseAcademico) debe implementar obligatoriamente.
  • Trabajo 2 (Polimorfismo): PrincipalPrueba guarda objetos de distintas subclases en un mismo arreglo ItemRecompensa[] y llama a aplicarEfecto() de forma genérica — cada objeto ejecuta su propia versión del método.

2. Archivos del proyecto

En Java, cada clase pública va en su propio archivo — por eso el código de la guía se separó en 4 archivos .java. Aquí tienes para qué sirve cada uno:

ItemRecompensa.java

La plantilla base (clase abstracta). Define QUÉ datos tiene todo ítem (nombre, costoPuntos) y OBLIGA a cada subclase a escribir su propia versión de aplicarEfecto(). No se puede crear un objeto directamente de esta clase (new ItemRecompensa(...) da error de compilación) — solo existe para que otras clases hereden de ella.

ItemAvatar.java

Subclase hija 1. Hereda de ItemRecompensa (extends) y define CÓMO se comporta un ítem tipo avatar: al llamar aplicarEfecto(), imprime el mensaje de desbloqueo de la skin.

ItemPaseAcademico.java

Subclase hija 2. También hereda de ItemRecompensa, pero con su propio comportamiento: al llamar aplicarEfecto(), imprime el mensaje de otorgamiento del pase.

PrincipalPrueba.java

El punto de entrada — este es el que se ejecuta. Contiene el método main(), crea el arreglo polimórfico y demuestra que cada objeto responde distinto al mismo mensaje. Es el único archivo que debes correr (Run); los otros tres son las clases que él usa.

¿Y los archivos .class?

Cuando compilas con javac (o presionas Run en el IDE), por cada archivo .java se genera automáticamente un archivo .class del mismo nombre (por ejemplo, ItemAvatar.java → ItemAvatar.class). Ese .class es el bytecode: la versión "traducida" del código que la máquina virtual de Java (JVM) puede ejecutar directamente — es lo que realmente corre cuando escribes java PrincipalPrueba.

Puntos clave para el alumno:

  • Nunca edites un .class a mano — no es legible ni editable como el .java, es código binario intermedio.
  • Si borras todos los .class, no pierdes nada: se vuelven a generar compilando de nuevo (javac *.java). Por eso muchos proyectos ni siquiera los guardan en el control de versiones.
  • Si modificas un .java pero no vuelves a compilar, el .class queda desactualizado y seguirás ejecutando la versión vieja del programa.

3. Requisitos

Solo necesitas el JDK instalado (versión 17 o superior). Gratuito en adoptium.net (Eclipse Temurin).

✅ Verificar instalación

En una terminal: javac -version. Si responde con un número de versión, ya está listo.

4. Ejecutarlo por terminal

PASO 1

Ubícate en la carpeta del código:

$ cd Sesion-03/codigo
PASO 2

Compila todos los archivos .java a la vez:

$ javac *.java
PASO 3

Ejecuta la clase que contiene main:

$ java PrincipalPrueba

5. Ejecutarlo con un IDE (recomendado para editar)

Abre la carpeta Sesion-03/codigo como proyecto en cualquiera de estos IDEs gratuitos, y ejecuta el archivo PrincipalPrueba.java (es el que tiene el método main):

Apache NetBeans

Clic derecho sobre PrincipalPrueba.java → Run File.

IntelliJ IDEA Community

Abre la carpeta como proyecto, clic derecho sobre main → Run.

Eclipse IDE

Importa la carpeta, luego Run As → Java Application sobre PrincipalPrueba.

VS Code

Instala Extension Pack for Java, abre PrincipalPrueba.java y pulsa Run sobre main.

6. Salida esperada en consola

Al ejecutar, la terminal debe imprimir exactamente esto:

--- EJECUTANDO EFECTOS CON POLIMORFISMO ---
Ítem: Skin Guerrero Cyber | Costo: 150 pts
Desbloqueando skin de avatar tipo: Legendario
--------------------------------------------------
Ítem: Pase de Prórroga | Costo: 300 pts
Otorgando pase académico especial por 7 días.
--------------------------------------------------
  • El primer ítem imprime "Desbloqueando skin de avatar tipo: Legendario" (viene de ItemAvatar.aplicarEfecto()).
  • El segundo ítem imprime "Otorgando pase académico especial por 7 días." (viene de ItemPaseAcademico.aplicarEfecto()).
  • Ambos mensajes son distintos aunque el for recorre el arreglo con la misma referencia ItemRecompensa — eso es el polimorfismo en acción.

7. Problemas comunes

⚠️ Solución a errores frecuentes

❌ class ItemAvatar is public, should be declared in a file named ItemAvatar.java

✅ Cada clase pública necesita su propio archivo con el mismo nombre. Por eso este proyecto usa 4 archivos separados en vez de uno solo.

❌ cannot find symbol: class ItemAvatar al compilar PrincipalPrueba.java solo

✅ Compila todos los archivos juntos con javac *.java, no uno solo — PrincipalPrueba depende de las otras 3 clases.

❌ Olvidar super(nombre, costoPuntos) en el constructor de una subclase

✅ Como ItemRecompensa no tiene constructor vacío, cada subclase debe llamar a super(...) como primera línea de su constructor.
